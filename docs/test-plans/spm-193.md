# SPM-193 coordinator notifications

Story SPM-193 (epic SPM-31), subtasks SPM-260 to SPM-269, on
`feature/SPM-193-coordinator-notifications`. The coordinator Notifications page
(SPM-268) is the frontend part of the same story.

## Coordinator notices for workflows that do not exist yet

Call each with `PERFORM` inside the workflow's own function, after its writes,
so the notice commits or rolls back with the action. Each goes to the event's
coordinator at the time of the call (none if unassigned or inactive) and sets
an action key, so a repeated call writes nothing.

| Caller | Function | Action key |
| --- | --- | --- |
| SPM-188 hold reminder (AC8) | `_notify_coordinator_hold_expiring(event_id, hold_id, venue_id, expires_at)` | `HOLD_EXPIRING:{hold}:{expiry}`, so an extended hold warns once more |
| SPM-188 hold expiry (AC8) | `_notify_coordinator_hold_expired(event_id, hold_id, venue_id)` | `HOLD_EXPIRED:{hold}` |
| Venue block on a booking (AC5, Master 5.4.4) | `_notify_coordinator_venue_blocked(event_id, block_id, venue_id, reason)`; reason is the block's reason code | `VENUE_BLOCKED:{block}:{event}:COORDINATOR` |
| Technical decision (AC6) | `_notify_coordinator_technical_decision(event_id, request_key, 'APPROVED' or 'REJECTED', reason)`; a rejection needs its reason | `TECHNICAL_REQUEST_{decision}:{request}:COORDINATOR` |

Hold, block and request IDs must match `[A-Za-z0-9_.-]{1,64}`.

## API

`/api/notifications` (list, unread count, mark one, mark all) is open to
`ATTENDEE`, `ORGANISER` and `COORDINATOR`; other roles get `403`. A hidden or
another user's notification is `404`. Coordinator targets are `EVENT_WORKSPACE`
(`/events/<id>`); after reassignment that page is `404` for the previous
coordinator (AC9).
